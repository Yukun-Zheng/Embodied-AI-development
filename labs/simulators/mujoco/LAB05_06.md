# MuJoCo Cross-Layer — Lab 05 Dynamics → Lab 06 Control

The first three MuJoCo references validate isolated primitives:

```text
Lab 04: kinematics / Jacobian
Lab 05: rigid-body dynamics
Lab 06: feedback control
```

This experiment closes the first **cross-layer causal chain**:

```text
assumed dynamics model
→ computed-torque command
→ actuator limits
→ MuJoCo physical transition
→ tracking / recovery / saturation
```

The goal is to stop treating "model mismatch" as an abstract prediction metric. The same mismatch measured in Lab 05 is injected into a real closed-loop controller.

## 1. Shared physical task

All conditions control the same MuJoCo 3R arm and track the same smooth joint trajectory for 5 seconds.

The desired state provides

\[
q^*(t),\quad \dot q^*(t),\quad \ddot q^*(t).
\]

Every controller receives the same state, actuator limits and generalized-force disturbance:

```text
t = 2.00 s → 2.18 s
qfrc_applied = [-2.5, 1.7, -1.2]
```

## 2. Matched computed torque

The desired acceleration is

\[
a_c = \ddot q^* + K_p(q^*-q)+K_d(\dot q^*-\dot q).
\]

Using the engine-matched model,

\[
\tau = M(q)a_c + h(q,\dot q)-\tau_{passive}.
\]

Because MuJoCo itself evolves

\[
M(q)\ddot q = \tau + \tau_{passive} - h + \tau_{external},
\]

the controller should approximately realize \(a_c\) away from actuator saturation and external disturbances.

## 3. Model-error conditions

### `computed_torque_wrong_mass`

Use

\[
\hat M=0.6M
\]

while keeping bias and passive-force terms correct.

This reuses the same inertia mismatch as the Lab 05 dynamics reference and measures its closed-loop consequence.

### `computed_torque_omit_passive`

Use the true mass matrix and bias force but do not compensate passive damping.

### `plain_pd`

Use the same feedback gains without any dynamics feedforward:

\[
\tau=K_p(q^*-q)+K_d(\dot q^*-\dot q).
\]

This is not a "bad controller" by definition; it is a model-free feedback baseline under the same torque limits.

## 4. What is measured

For every time step:

- actual and desired joint state;
- position / velocity error norm;
- raw model-based torque;
- saturated torque;
- whether any actuator saturates;
- whether the shared disturbance is active.

Per condition:

- joint-position RMSE;
- joint-velocity RMSE;
- maximum position-error norm;
- error at disturbance end;
- late-window recovery error;
- control energy;
- saturation fraction.

## 5. Falsification logic

The intended claim is not "computed torque always wins." It is narrower:

> A dynamics error that is measurable at the acceleration-prediction level should produce a measurable physical control consequence when the same wrong model is placed in the controller.

The experiment fails if:

- matched computed torque cannot track the reference trajectory;
- the shared disturbance cannot be recovered from;
- the 40% mass mismatch is physically indistinguishable from the matched model;
- omitting passive dynamics is completely invisible in tracking/recovery;
- plain PD and model-based control cannot be distinguished under the chosen trajectory;
- differences arise only because one condition receives different torque limits or disturbance.

## 7. Scientific interpretation

This is the first textbook experiment where a quantity validated in one layer becomes an intervention in the next layer:

```text
Lab 05 acceleration-model error
            ↓
controller feedforward error
            ↓
actuator command difference
            ↓
MuJoCo trajectory difference
            ↓
tracking / recovery / energy consequence
```

That cross-layer chain is closer to how mechanism research should be done in embodied AI: do not stop at proving an internal metric changes; show where it enters physical behavior.

## 8. Next extension

After this experiment is stable, the same structure can be reused for:

- MPC with matched vs biased world dynamics;
- impedance control with incorrect inertia / damping;
- contact-rich manipulation where model mismatch changes contact forces;
- sim-to-real parameter identification and controller robustness.
